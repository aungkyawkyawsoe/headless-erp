Design reference — variant C

Signed-in role: — the ⋮ menu offers only what this role may do.

Front — steering axle

On the wheels · equipped

Try: tap a mounted tyre (opens its ⋮ actions), tap a vacant wheel (wear a spare), take one off, or switch the role.

1 · MECE — the state model

Every unit on this truck is in exactly one state; no overlap, nothing missing.

State Data Colour
Fitted slot ≠ null tread band
Un-worn slot = null grey
In store holder = store not here

Two segments exhaust the kinds: Tyres (fitted + un-worn) and Equipment. No "All" tab — it would only restate the two.

2 · Poka-Yoke — the ⋮ menu cannot be wrong

  • The action list is built from the row's state: a fitted tyre offers Change / Take off / Transfer; an un-worn tyre offers Wear / Transfer. You cannot "wear" something already on a wheel.
  • An impossible action is shown disabled with its reason ("No vacant wheel") — not hidden — so the operator learns the constraint instead of hunting.
  • Transfer always states "needs superior approval", so nobody expects it to complete on tap.
  • The server re-checks every rule (mro_asset_requests + moveSerialAsset guards) — the UI is a hint, never the gate.

3 · PoLP — least privilege

Switch the role in the toolbar and reopen a ⋮ menu:

  • Technician — wear · take off · change · file a transfer.
  • Supervisor — adds Scrap / write-off.
  • Admin — adds Force correct (governed override).
  • Filing a transfer is allowed for the holder; deciding it is not — that lives in the Approval center, scoped to a recorded superior or an admin.

4 · STRIDE — threat → mitigation

S Session-stamped actor. requested_by / actor_fields come from the signed JWT, never the payload — a body id cannot impersonate.
T Frozen columns + guarded CAS. status/approved_by/… are stripped from generic writes; every move is one atomic guarded batch. A unit that moved since approval is 409, never silently relocated.
R Append-only evidence. Each change writes an immutable mro_serial_events row with actor + ref doc (ATR-…) — nobody can deny a move.
I Scoped reads. RBAC per collection; offline persistence is deny-by-default; the ⋮ menu reveals nothing the role may not use.
D Bounded + idempotent. One holder read, keyset pagination, no unbounded scans; writes carry an Idempotency-Key so a retry is not a second move.
E Two-person + service-only writes. A decider cannot be the requester; the RBAC admin bypass cannot reach a mode:'service' table.

5 · PASTA — attack scenarios

  • Hide a loss: move a dangerous tyre to a truck to bury the reading → the tile stays banded by the measured mm; a measured tyre is never re-tinted by guess, and the event log names the actor.
  • Double move: replay the execute → status is a compare-and-set and the request pins its source, so the second attempt is 409.
  • Ghost custody: claim a tool was handed over → custody changes only through the guarded writers, and the session stamps who did it.
  • Privilege creep: a technician tries to write off → Scrap is absent from the role's menu and rejected server-side.

Colour language

Fitted · good ≥ 5 mm Fitted · warn 3–5 mm Fitted · replace < 3 mm Un-worn / equipment

Colour is reserved for a live safety state on a wheel. Off the wheel a tyre is grey — so a glance at the rig tells you the running condition, with no colour noise from stock.

Static design reference only. A and B were dropped in favour of C — rig context is preserved and the layout holds from 4 to 24 wheels.
